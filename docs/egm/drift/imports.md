## backend/app/modules/imports/README.md

Re-checked 2026-11-13 against the working tree. The two earlier [contract] items and the earlier [undocumented]/[wording] items are fixed (README Flow now lists all routes, upload codes, `nothing-to-import`, `already-exists`; docs/api/openapi-core.yaml:1520-1599 now has source, dry-runs, commits, error-report and no cancel). Remaining divergences:

- [wording] README lines 10-11 say the importer has "two import-linter contracts: it may call platform, clients, memberships, billing, pos and engagement only". The contract at backend/pyproject.toml:392-399 is a `forbidden` list of the twelve other contexts, not an allow-list, so a newly added context is not blocked for `imports` until someone adds it to that list (the "no context imports it" contract at :404-411 likewise lists sources by name).
- [wording] README lines 180-181 say POS products "follow the catalogue's bounds" and give price at most 999,999,999.99. That limit is not the catalogue's (pos/schemas.py:15 allows up to 10**12 minor units); it comes from the import's own nine-digit money pattern (backend/app/modules/imports/csvio.py:20), which applies to every money column.
- [undocumented] Money cells of every type (price, term price, amount) are capped at nine integer digits (csvio.py:20, `money` at :161-167), so a shared limit below the catalogue's and below billing's. README line 146 lists only "two-decimal, no sign, no separator".
- [undocumented] Household handling in client rows is not described. Household heads are processed first (service.py:285-290), a row with `household_ref` needs exactly one head row in the file, otherwise it is invalid with code `household` ("No row is marked head of this household.", "This household has two heads.", "The household head (row N) was not imported.") (service.py:293-305, 372-383; kinds.py:172-174 for head-without-ref and head-with-relationship). README line 116 says only that "links are made directly".
- [undocumented] Free-text cells are screened for card numbers; a row whose free-text field looks like a card number is refused with the shared `CARD_DATA` code (service.py:352-357, security-baseline 3). Not listed in the README row outcomes or limits.
- [undocumented] `GET /import-jobs/{id}` (router.py:59-61) is not in the Flow section (README lines 38-60), nor are the job view fields a client reads: `processed_row_count`, `source_file_name`, `has_error_report`, `stop_reason` (service.py:92-104). README line 72 mentions only "Stopped" in the UI.
- [undocumented] The error report exists only when at least one row has a problem or warning (service.py `_write_report`, early return at `len(lines) == 1`); otherwise `GET /import-jobs/{id}/error-report` is 404 "This import has no error report." (service.py:255-258), also after file purge. README lines 58-61 imply it is always available.
- [undocumented] Every route carries the `idempotency` dependency (router.py:17) and CSV downloads are sent with `nosniff` and `private, no-store` headers (router.py:35-40); dry-run and commit answer 202 and run asynchronously (router.py:75, 85). `POST /import-jobs` also refuses a non-staff principal and an unknown location (422, pointer `/location_id`) (service.py:148-155). None is in the README.
