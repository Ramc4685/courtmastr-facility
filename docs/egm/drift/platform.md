## backend/app/modules/platform/README.md

Re-checked against the code on main (2026-11-13, third pass: platform line numbers, yaml line numbers and the `PATCH /me` claim re-verified). README line numbers are the current ones. The only branch change in platform is the leagues key count in `tests/test_rbac.py:51` (16 to 15); the README states no per-context key counts, so that edit causes no drift (the platform count of 31 at README:15 still matches `test_rbac.py:49` and `:235`).

Items from earlier reports that the README has since fixed are left out: file table now lists `events.py`, `router.py`, `schemas.py`, `models.py`; the "Not built yet" paragraph names the five unused keys; `auth.sessions` and `retention` / `audit` config names; the `linked_resource_id` FK and report-result purge are no longer listed as missing. An earlier claim that `PATCH /tenant` cannot clear a brand colour was wrong: the route uses `model_dump(exclude_unset=True)` (`router.py:361`), so an explicit null clears it.

- [contract] README:23 says "Other contexts use `service`, `auth` and `staff` only, never the models". Non-test code in other contexts imports `platform.models` directly: `clients/files.py`, `clients/households.py`, `clients/activity.py`, `reporting/service.py`, `reporting/schedules.py`, `imports/service.py`, `documents/service.py` (`StoredFile`, `Identity`, `TokenPurpose`, `StaffUser`; for example `clients/files.py:29`, `clients/households.py:383,449`, `clients/activity.py:269-270`, `reporting/service.py:400`, `reporting/schedules.py:176`). They also call `files`, `entitlements`, `retention`, `onboarding`, `privacy`, `oidc`, `mfa`, `rbac`, `tenant_export` and `branding`, several of which the README itself presents as cross-context APIs (README:17-18, 346-348, 391-395). The rule needs rewording or the imports need moving behind `service`.
- [wording] README:5 says the module "Calls no other context", but README:23-24 documents `privacy` as an exception, and `privacy.py:89` imports `app.modules.clients.service` (lazily, to load a client at `privacy.py:92`). Line 5 contradicts line 23.
