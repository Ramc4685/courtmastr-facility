## backend/app/modules/memberships/README.md

- [missing] README:60 says `catalog_item_id` is not created because its table does not exist. The column does exist, with a composite FK to `catalog_item`, on `membership_plan_addon`, `membership_contract_addon` and `billing_schedule_period` (`backend/app/modules/memberships/models.py:222,234,372,384,397,430`), and `catalog_item` is a billing table (`backend/app/modules/billing/models.py:959`). The `models.py` docstring the README defers to (README:11) is stale in the same way: it says "an add-on is a package plan only" (`models.py:4-5`), yet README:83-84 describes item add-ons.
- [wording] README:60 says the tables for `coupon_id` and `payment_method_id` do not exist. Both now do: `coupon` (`backend/app/modules/billing/models.py:659`) and `payment_method` (`billing/models.py:734`). The columns are still absent from memberships, so the stated reason is stale even though the omission is real.
- [stale-not-built] README:55 lists "member card rendering (MEM-19)" as not built. Printed member cards exist in `access`: `IdCardTemplate` is described as "What a printed member card shows (CHK-12, MEM-19)" (`backend/app/modules/access/models.py:159-163`).
- [stale-not-built] README:55 lists "MEM-21 reports and `rpt_*` views" as not built. `rpt_membership_contract` is defined in `backend/app/modules/reporting/views.py:39-57` and created by `backend/migrations/versions/0953_reporting_core.py`.
- [stale-not-built] README:55 lists "MEM-22 API keys" as not built. An `api_key` model exists in the integrations context (`backend/app/modules/integrations/models.py:1,14`). Unverified: whether those keys cover the MEM-22 membership API scope.
- [stale-not-built] README:50 says "Coupons on a contract" are not built. The portal sale accepts `coupon_code` (SSP-11) (`backend/app/modules/memberships/schemas.py:243`) and passes it to `billing.checkout.secure_online_checkout` (`backend/app/modules/memberships/service.py:1966`), so a coupon can discount the sale invoice online. No coupon is stored on the contract, and staff sales take none.
- [wording] README:47-48 lists "the card-save modes at sale" as not built without saying the setting exists. `membership_settings.online_card_save_mode` (`always | when_nothing_due | ask`) is stored and exposed (`backend/app/modules/memberships/models.py:244,253`, `schemas.py:171,183`), but nothing in `service.py` reads it. Line 54 already uses a "stored only" note for `freeze_resume_invoice_mode`; this setting needs the same note.
- [undocumented] README:25-27 (internal interface) leaves out functions other contexts call: `get_contract` (`backend/app/modules/access/service.py:111`), `seller_periods` (`backend/app/modules/staff/service.py:1443`, definition `memberships/service.py:2185`), and `run_daily` and `import_contract` (imports). The last two are named elsewhere in the README but not as part of the interface.
- [undocumented] The README never mentions the client merge and erasure handlers, including the merge precheck that blocks two overlapping memberships (`backend/app/modules/memberships/service.py:2072,2128-2129`).
- [undocumented] Apart from `memberships.contract.activated` (README:63-64), the README never lists the events this module publishes: `ContractRenewed`, `ContractFrozen`, `ContractUnfrozen`, `ContractSuspended`, `ContractCancelled`, `ContractExpired` (`backend/app/modules/memberships/events.py:16-51`).
