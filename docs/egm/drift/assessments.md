## backend/app/modules/assessments/README.md

- [stale-not-built] **"Not built: mobile screens" is stale (README line 52).** The mobile app has a Progress screen built on the portal bests route: `mobile/src/app/progress.tsx:17-21` uses `listProgress` → `GET /portal/assessment-bests` (`mobile/src/adapters/api.ts:177`), and `mobile/README.md:45` lists it.
- [undocumented] **"A result needs a location" is only an API rule (README lines 37-38).** `location_id` is required in the create schema (`assessments/schemas.py:109`). The column itself is nullable (`assessments/models.py:76`; `backend/migrations/versions/0952_assessments_core.py:77`). `delete_result` keeps a branch for a null location that needs tenant-wide `assessment.delete` (`assessments/service.py:247-248`). The README says neither of these.
- [undocumented] **Permission list leaves out a registered key (README lines 24-26).** `assessments.assessment.share` (a `C` key, own reach for coaches) is registered (`assessments/permissions.py:17`; rbac-matrix 6.16) but missing from the Interfaces list. The feature it gates (`shareAssessmentResult`, `docs/api/openapi-people.yaml:5821`) is listed as not built (README line 52), and no service or route uses the key.
- [contract] **Delete needs a second gate (README line 25).** The doc gives `assessment.delete` as an `L` key on the entry's location. `delete_result` first loads the entry through `_result(..., READ)`, which also requires reaching the client with `assessments.assessment.read` (`assessments/service.py:156-161, 246`). Only then does it check the `L` key (`service.py:247-250`).
- [undocumented] **Data-subject export is not documented (README line 29).** The doc says only "Merge moves every entry...; erasure deletes the client's entries (`subject.py`)". `subject.py` also registers an export handler (`assessments/subject.py:19-28, 39`) that returns every entry's `recorded_at`, staff `note` and values.
- [wording] **History filters are documented on both reads, but the list has fewer (README lines 15-16).** "Filters: field ids, category, time window" follows both `listAssessmentResults` and `getAssessmentSeries`. Only the series takes field ids and category (`assessments/router.py:107-118`; `service.py:259-270`). `list_results` allows only `client_id` and `recorded_at` filters (`service.py:196`).
- [undocumented] **Web screens are not mentioned.** `web/src/features/assessments/AssessmentSetupPage.tsx`, `ClientAssessmentsTab.tsx` and `PortalProgress.tsx` implement setup, the client history tab and the portal view; `web/src/features/portal/ProgressPage.tsx` and `PublicProgressPage.tsx` implement share-link management and the anonymous page. The README has no screens section or pointer to them.
- [contract] **Progress share link routes are not in the API contract (README lines 56-63).** `docs/api/openapi-people.yaml` has no `/portal/progress-share-links`, `.../{id}/revoke` or `/public/progress-shares/lookup` operation. The only FIT-05 entries are `shareAssessmentResult` (line 5821) and the portal results and bests reads. The routes live at `assessments/router.py:136-165`. The README does not say they go beyond the spec.
- [undocumented] **Share links are not covered by merge or erasure (README line 29, lines 56-63).** `subject.py:37` lists only `assessment_result` and `assessment_result_value`, so `progress_share_link` rows are neither repointed on merge nor exported or erased for a data subject request. They hang off the client only through the cascading FK (`assessments/models.py:130`). The README's merge and erasure line and the share link section both leave this out.
- [undocumented] **Share link create and list details are missing (README lines 58-61).** `POST /portal/progress-share-links` also takes `client_id`, defaulting to the signed-in client, for guardians (`assessments/schemas.py:173`; `service.py:395`). Create, list and revoke all answer 404 while portal sharing is off (`service.py:293-296`; `router.py:138`). The lookup response also carries `expires_at` (`schemas.py:203`). The audit key `assessments.share_link.manage` is a plain string with no registered permission behind it (`service.py:368`), so staff cannot view or revoke a client's links.
