## backend/app/modules/rentals/README.md

Checked 2026-11-13 against the working tree and the rentals operations in `docs/api/openapi-core.yaml`. Read-only; no tests run. Only divergences are listed. Code paths are under `backend/app/modules/rentals/` unless stated.

- [stale-not-built] `models.py:1-2` says `locker_lease` "is not built" and that resources' `locker` and `locker_term` tables do not exist. `LockerLease` is defined at `models.py:598` and README L89-101 describes lockers as built.
- [missing] README L140-141 says confirmation decides "secured" through `billing.checkout.is_secured`. Rentals never calls it (only `billing/checkout.py:34,103,115` use it). `confirm_portal_rental` (`service.py:1599-1610`) passes the `secure_online_checkout` result through, and `service.py:1560` reports `payment_status` without a secured test.
- [contract] `confirmPortalRental` field name. Code uses `save_method` (`schemas.py:463`) and README L156-157 agrees. The contract `PortalRentalConfirm` (`openapi-core.yaml:6149`) names it `save_payment_method`.
- [contract] `confirmPortalRental` errors. README L158-159 says a decline is 409 `payment-failed` (`router.py:198`). The contract declares 402 PaymentDeclined and `x-problem-codes: [payment-declined, hold-expired, ...]` (`openapi-core.yaml:4170,4175`). README L156 says a stored method that is not the client's gives 422 `payment-method-not-usable`. The contract says 403 (`openapi-core.yaml:6141-6143`). `payment-method-required` (`service.py:1604`) is not in the contract either.
- [contract] `GET` and `PUT /locations/{location_id}/rental-portal-settings` (`router.py:161,166`; README L145-148) have no operation in any `docs/api/*.yaml`. `openapi-programs.yaml:97` only mentions them in prose. `horizon_days` (`schemas.py:87,419,473`) and the `beyond-horizon` code (`service.py:1386`; README L154-155) are also absent from the contract.
- [contract] Three routed operations have no `operationId` in the contract: `PATCH /rental-plan-purchases/{purchase_id}` (`router.py:264`, `service.py:1865`), `POST /portal/rental-plan-purchases/{purchase_id}/auto-renew-opt-out` (`router.py:305`) and `POST /locker-leases/{locker_lease_id}/renew` (`router.py:336`). README L15 says the router serves "the rental routes of `openapi-core.yaml`". The reverse also holds: the contract defines `updateRental` (`openapi-core.yaml:3893`), which README L128 correctly lists as not built.
- [undocumented] The portal confirm records the client's acceptance of the portal terms: `clients.terms.acknowledge(...)` at `service.py:1599`, with `terms_version_id` at `schemas.py:464` (SSP-14). README L156-159 describes the payment step only. The cross-context list (L84-87) omits `clients.terms`.
- [undocumented] The file table (L7-16) omits `schemas.py`, `permissions.py`, the lockers screen `web/src/features/lockers/LockersPage.tsx`, the portal screens (`web/src/features/portal/BookingsPage.tsx`) and `web/src/features/rentals/RentalSetupPage.tsx` features beyond "types, rates, plans, plans sold" (L16).
- [undocumented] Permission keys not mentioned: `permissions.py:14-26` registers `rental_type.manage`, `rental_plan.manage`, `rental_plan.sell`, `rental_plan.share`, `rental_plan.remove` (flag D) and `public_listing.publish`. The README names only `booking.override_rate`, `booking.override_minor`, `portal_setting.manage` and `locker_rental.manage`, and has no key table.
- [undocumented] Routes with no description: `PUT /rentals/{id}/public-schedule` (`router.py:138`, `service.py:1032`), `POST /rental-plan-purchases/{id}/cancel` (`router.py:277`, `service.py:1835`), `PATCH /rental-plan-purchases/{id}` for auto-renew and autopay (`router.py:264`, `service.py:1865`), `DELETE /rental-plans/{id}` as archive (`router.py:237`, `service.py:1691`) and `POST /portal/rentals/{id}/abandon` (`router.py:203`, `service.py:1616`).
- [wording] README L9 says `models.py` has "13 tables". It defines 16 (`models.py:161-598`). Missing from the L9 list: `rental_portal_setting` (:221), `rental_plan_share` (:579) and `locker_lease` (:598).
- [wording] README L77 says "confirm takes no stored method". README L156-157 and the code (`schemas.py:462`, `service.py:1601`) accept `payment_method_id`, so the two passages contradict each other.
