Lookup refusals are 422 `lookup-method-disabled` (service.py:764-784). README 73-76 says only that minors are not listed.
- The kiosk cookie lives 400 days (`max_age=400 * 86400`, router.py:402). The README gives no lifetime.
- `kiosk.visit()` spends the visit token with one `DELETE ... RETURNING` (kiosk.py:51-68), so two concurrent taps cannot both spend it and the loser gets 404. README 96-99 states this; `test_a_visit_token_cannot_be_spent_twice_concurrently` (tests/test_kiosk_reservations.py:247) covers it, but the README names no test.
- The household lockout (new). `clients.households.household_ids` (households.py:353-365) is symmetric: the visitor's lockout comes from a past-due invoice billed to the visitor or to any client one live relationship away whose type grants acting rights in either direction. README 88-90 names only the child billed to a parent; a parent is equally locked through a child's past-due invoice (the test's own docstring says so). The only test, `test_a_child_billed_to_a_past_due_parent_cannot_book_at_the_kiosk` (`backend/app/modules/billing/tests/test_collections.py:76`), lives in billing and covers the child case only. Nothing in `access/tests/` covers the household lockout, and the README names no test.
- The README's reverted-purchase bullet gives rules for a future version (a fresh app-QR step, no bare wallet passes, one purchase per check-in, a daily cap) but no code, test or contract places mark them. Nothing in the code prevents a later purchase route from skipping them.

### [wording]

- README 109-110 says a typed member number is `name_search`. That holds for the number on the client record. A typed value that matches an active credential row (barcode, membership-number credential) resolves to a credential, so the match carries `credential_id` and the check-in is `identified_by = credential` (service.py:749-777; kiosk.py:30-31). The README should say "typed client-record member number".
- README 76, 90 and 99 use "admitted" for the kiosk status. The stored `check_in.result` is `granted` / `denied` / `granted_override` (models.py:32-35), and the kiosk response status is `admitted` / `see_staff` (kiosk.py:142). The README uses both vocabularies without saying which is which. README 13 is right for the stored value.
- README 149-150 puts "Booking from a check-in marks only the session just booked, and refuses a checked-out visit (409 `already-checked-out`)" inside the Member card (CHK-12) bullet. It belongs with "Book or sell from the window (CHK-04)" (README 133-138; desk.py:199, 224).
- README 105-106 says "Spending anything at the kiosk (a package credit, and in future a membership visit, an account charge or a payment)", while the next bullets say a package purchase was dropped; "a package credit" is the only spend the code does (through `programs.selfservice.kiosk_enroll`), so "Spending anything" reads wider than what is built.
- README 112 (name-search bullet) says auto-book "follows the same rule" as a name-search visit (free booking only), and README 113 says possession "unlocks the full portal rules". Since the free-only change (README 91-94; kiosk.py:166-171) auto-book books only free sessions for every identification, so the possession case no longer gets the full rules there. The bullets should say the full rules apply to a session the person picks, not to auto-book.
