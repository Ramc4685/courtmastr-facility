## backend/app/modules/rentals/README.md

Checked 2026-11-13 against the working tree and the rentals operations in `docs/api/openapi-core.yaml`. Read-only; no tests run. Only divergences are listed. Code paths are under `backend/app/modules/rentals/` unless stated. Refreshed after the availability change (`from_time`/`to_time`, `cursor`, `service.slot_page`); line numbers re-read where cited.

- [undocumented] The cursor encodes court name, court id and start (`service.py:1455-1474`). README L84-86 says so. The contract describes it only as "Opaque keyset cursor" (`openapi-core.yaml:4515`) and does not carry the "stable only while the day's holds do not change" caveat.
- [stale-not-built] `models.py:1-2` says `locker_lease` "is not built" and that resources' `locker` and `locker_term` tables do not exist. `LockerLease` is defined at `models.py:594` and README L89-101 describes lockers as built.
- [missing] README L140-141 says confirmation decides "secured" through `billing.checkout.is_secured`. Rentals never calls it (only `billing/checkout.py` uses it). `confirm_portal_rental` (`service.py:1620-1650`) passes the `secure_online_checkout` result (`service.py:1637`) through, and `service.py:1591` reports `payment_status` without a secured test.
- [contract] `confirmPortalRental` field name. Code uses `save_method` (`schemas.py:463`) and README agrees. The contract `PortalRentalConfirm` (`openapi-core.yaml:6155,6167`) names it `save_payment_method`.
- [contract] `confirmPortalRental` errors. README says a decline is 409 `payment-failed` (`router.py:201`). The contract declares 402 PaymentDeclined and `x-problem-codes: [payment-declined, hold-expired, ...]` (`openapi-core.yaml:4193`). README says a stored method that is not the client's gives 422 `payment-method-not-usable`. The contract says 403. `payment-method-required` (`service.py:1635`) is not in the contract either.
- [contract] `GET` and `PUT /locations/{location_id}/rental-portal-settings` (`router.py:163,168`) have no operation in any `docs/api/*.yaml`. `openapi-programs.yaml:97` only mentions them in prose. `horizon_days` (`schemas.py:87,419,473,481`) and the `beyond-horizon` code (`service.py:1388`) are also absent from the contract.
- [contract] Three routed operations have no `operationId` in the contract: `PATCH /rental-plan-purchases/{purchase_id}` (`router.py:267`, `service.py:1896`), `POST /portal/rental-plan-purchases/{purchase_id}/auto-renew-opt-out` (`router.py:308`, `service.py:2095`) and `POST /locker-leases/{locker_lease_id}/renew` (`router.py:339`). README L15 says the router serves "the rental routes of `openapi-core.yaml`". The reverse also holds: the contract defines `updateRental`, which README correctly lists as not built.
- [undocumented] The portal confirm records the client's acceptance of the portal terms: `clients.terms.acknowledge(...)` at `service.py:1630`, with `terms_version_id` at `schemas.py:464` (SSP-14). The README describes the payment step only, and its cross-context list omits `clients.terms`.
- [undocumented] The file table (README L7-16) omits `schemas.py`, `permissions.py`, `web/src/features/lockers/LockersPage.tsx`, the portal screen `web/src/features/portal/BookingsPage.tsx` (including its "Show more times" paging, `BookingsPage.tsx:303`, which README L86 does mention) and `web/src/features/rentals/RentalSetupPage.tsx` features beyond "types, rates, plans, plans sold".
- [undocumented] Permission keys not mentioned: `permissions.py:14-26` registers `rental_type.manage`, `rental_plan.manage`, `rental_plan.sell`, `rental_plan.share`, `rental_plan.remove` (flag D) and `public_listing.publish`. The README names only `booking.override_rate`, `booking.override_minor`, `portal_setting.manage` and `locker_rental.manage`, and has no key table.
- [undocumented] Routes with no description: `PUT /rentals/{id}/public-schedule` (`router.py:138`, `service.py:1034`), `POST /rental-plan-purchases/{id}/cancel` (`router.py:280`, `service.py:1866`), `PATCH /rental-plan-purchases/{id}` for auto-renew and autopay (`router.py:267`, `service.py:1896`), `DELETE /rental-plans/{id}` as archive (`router.py:240`, `service.py:1722`) and `POST /portal/rentals/{id}/abandon` (`router.py:206`, `service.py:1647`).
- [wording] README L9 says `models.py` has "13 tables". It defines 16 tenant tables. Missing from the L9 list: `rental_portal_setting` (`models.py:217`), `rental_plan_share` (:576) and `locker_lease` (:594).
- [wording] README L77 says "confirm takes no stored method". README L156-157 and the code (`schemas.py:462`, `service.py:1635`) accept `payment_method_id`, so the two passages contradict each other.
