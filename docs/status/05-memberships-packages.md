# Module 5: memberships and packages (contexts `memberships`, `packages`)

Branch `lane/people`, migration `0203_memberships_packages`. Module READMEs:
`backend/app/modules/memberships/README.md`, `backend/app/modules/packages/README.md`.

**Scope of this build: backend only.** No web screen exists for module 5, so nothing below is usable from the
web app yet. "done" means the API, the service rules, the daily job and the tests are in place; "partial" names
what is missing; the "Where" column lists operation ids (all under `/api/v1`).

**Nothing schedules the daily jobs yet.** `run_membership_day` and `run_package_day` are tenant actors that are
idempotent and catch up missed days, but the kernel has no scheduler, so renewals, schedule billing, status
transitions, expiries and recurring periods happen only when someone enqueues or calls them. Entitlement reads
do not depend on the jobs (they derive status from the dates).

**Not collected automatically.** Billing has no stored payment methods, autopay or dunning yet (build module 8):
invoices are created on time, and are paid at the sale, at the desk or in the portal purchase.

Tests: `backend/app/modules/memberships/tests/` (126) and `backend/app/modules/packages/tests/` (40), plus the
generated tenant-isolation, RLS, security and RBAC-matrix suites, which now cover the 17 new tables and 77 new
routes. Whole backend suite: 1231 passed, 0 skipped. Coverage: `memberships/domain/schedule.py` 100%,
`memberships/service.py` 95%, `packages/service.py` 95%; domain gate 95% (minimum 80%).

Counts (39 features): **P0** 10 done, 5 partial, 0 not built. **P1** 14 done, 4 partial, 3 not built.
**P2** 1 done, 2 not built.

Test file names below are short for `memberships/tests/test_schedule.py`, `test_sale.py`, `test_lifecycle.py`,
`test_renewal_jobs.py` and `packages/tests/test_packages.py`, `test_credits.py`.

## Assumptions made (full list in the module READMEs)

- Freeze follows ADR 0005 section 4 (billing restarts on the resume date and steps by cadence) where the data
  model says "shift by the frozen days".
- A cancel reverses billed periods that start after the cancel date whether or not they were paid; paid money
  becomes account credit.
- A future-dated cancel is kept as a cancel reason on a live contract and closed by the daily job.
- Proration is offered for monthly and yearly cadences only.
- Removal of a package with billing reversal is refused once sessions were used.
- A package bound to a document refuses the sale until the document is accepted; a membership instead waits
  as `upcoming`.

## Known defects and gaps

- No scheduler: see the top of this file.
- A freeze does not move a suspension that was scheduled after it (the suspension keeps its calendar dates).
- A recurring series whose plan has a document bound "every purchase" cannot restart itself; the job reports
  it in `failed` each day until staff act.
- Threshold auto-renew bills the successor inside the booking that triggered it; if that billing fails (for
  example the client was disabled) the booking fails with it.
- `reservation_type_id` is not validated against a table (see PKG-01).
- `web-e2e` and `pnpm build` were not run for this build (no web source changed except the regenerated
  `schema.d.ts`; `web-check` and `web-test` pass).
