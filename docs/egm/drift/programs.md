## backend/app/modules/programs/README.md

- [contract] `POST /portal/enrollments` (`createPortalEnrollment`) takes `direct_link_token`, but the contract does not. `PortalEnrollmentCreate` in `docs/api/openapi-programs.yaml:7445` lists only `client_id`, `session_id`, `pricing`, `client_package_id` and `registrant_comment`, and sets `additionalProperties: false`. `x-problem-codes` for the operation (`docs/api/openapi-programs.yaml:1405`) and its description don't mention the direct-link waiver either. Code and `backend/openapi.json:45734` carry the field (`backend/app/modules/programs/schemas.py:535`). README lines 53-56 document it, so the YAML is the stale side. A strict client generated from the YAML would be rejected for sending the token.
- [contract] The same schema keeps `pricing` and `registrant_comment` (`docs/api/openapi-programs.yaml:7445-7460`), which `PortalEnrollmentCreate` doesn't have (`schemas.py:531-535`). Free booking is decided by `seat["allows_free_booking"]` instead (`backend/app/modules/programs/selfservice.py:216`). With `additionalProperties: false` on both sides, a client sending either field gets a 422.
- [logic] The direct-link waiver covers `portal_enroll` only. `portal_join` and `portal_claim` call `_bookable_seat` and `_verdict` without `linked` (`selfservice.py:297`, `:343`), and `list_listings` never passes it (`:182`). For a full session reached by link, a hidden or list-only session or one beyond the visible range gives `422 Unknown session` or a `policy-violation` on the waitlist, and there is no link route to queue. The README (lines 53-56) states the waiver for enrolment only and doesn't say the waitlist and claim are excluded.
- [undocumented] `has_live_link` is checked before `_bookable_seat`, and a wrong or inactive token is not an error: it silently becomes `linked=False` (`selfservice.py:205`, `backend/app/modules/scheduling/service.py:842-848`). A bad token on a hidden session reports `422 Unknown session`, and on an unlisted one the normal listing rules. The README doesn't say so. `unlisted` stays bookable without a token by design (`selfservice.py:187`).

README lines 46-48 therefore describe an outdated plan.
