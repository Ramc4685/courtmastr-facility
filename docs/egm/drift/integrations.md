Re-verified 2026-11-13 on branch `claude/coach-share` against the 200-line README. Read-only; no tests run. Divergences only. Code paths are under `backend/app/modules/integrations/` unless they start with `backend/`, `docs/`, `config/` or `infra/`. The contract is `docs/api/openapi-programs.yaml` (operation lines are the `operationId` line; components `ExternalConnection` 9392, `SyncMapping` 9430, `AccountingExport` 9454, `VideoMeeting` 9481). Router routes, `KEY_CONTEXTS`/`KEY_PERMISSIONS`/`KEY_WITHHELD` and the `populate()` return (no `video_meeting` or `public_schedule_setting` id) were re-checked against the current tree; the only integrations change on this branch is a comment in `service.py:67-69` (staff stays off the allow-list, now also for coach payouts), which the README line 37 still covers.

### API keys and the key surface

- [contract] README 36-37 ("integrations ... off it"); `service.py:68-72` (`KEY_CONTEXTS` has no `integrations`). The contract marks 28 integrations operations `security: [{staffSession: []}, {apiKey: []}]` (`createApiKey` 6529, rotate, revoke, `listWebhookEventTypes`, the webhook, delivery, connection, mapping, export, sync, adapter and adapter-command operations). Every one is gated by an `integrations.*` key, so a key always gets `403 api-key-not-allowed`. Only the video-meeting operations (gated by `scheduling.session.manage`) are key-callable.
- [contract] README 38-41 (engagement single keys "as the contract ... allow"); `service.py:77-81`. 22 engagement operations whose `x-permission` is in `KEY_PERMISSIONS` (`scheduleCampaign` 5655 through `previewCampaignAudience` 6126, the media-asset, home-screen, app-tile, portal-content, location-content and trial-request operations) declare no `security`, and the file has no top-level `security`. The code lets a key holding the scope reach them; the contract does not say so.
- [undocumented] README 38-42 ("including the bulk `campaign.send` and `push.send`", "confirmed when they move money (`$`) or set prices (`P`)"); `service.py:56, 169`; `backend/app/modules/engagement/permissions.py:18, 21` (flag `B`). A key may hold the two bulk-send scopes without `confirm_sensitive_scopes`. The README does not say they skip the confirmation every other sensitive flag gets.
- [undocumented] README 10 (`auth.py` row), 35-46; `auth.py:95-97, 103-104`, `service.py:160, 194`. Authentication refuses a key when the tenant is not active (`403 tenant-suspended`) and when the plan lacks `api_access` (the same gate is on create and rotate), and writes `last_used_at` at most once a minute. None is in the README.
- [undocumented] README 45 ("migration 1705 stripped those outside the allowed contexts"); `backend/migrations/versions/1705_integrations_key_scope_allow_list.py`. Revision 1705 was rewritten in place to keep the seven engagement keys; a database that ran the old 1705 keeps the stripped scopes. The migration keeps its own copies of both lists with nothing tying them to `service.py:68-81`.
- [undocumented] README 41, 45 (`KEY_WITHHELD`; "a stored withheld key stays but is ignored"); `service.py:86-91`, `auth.py:62-64`. Accurate for runtime, but migration 1705 keeps every `rentals.*` scope, so the stored scope is never removed from `api_key.scopes`.
- [wording] README 37 ("platform, reporting, integrations and staff are off it"); `service.py:68-72`. `imports` is also off the allow-list and is not named.
- [wording] README 35-45; `models.py:60-61`. The `ApiKey` docstring says grants are "scopes intersected with the creator's current grants"; `auth._bounded` (`auth.py:49-66`) also drops scopes off the allow-list.

### INT-07 QuickBooks Online

- [contract] README 75-79 (callback is a POST); `router.py:159-168`, `schemas.py:176-190`. `completeExternalConnectionOAuth` (6889) is still an anonymous `GET` with query parameters answering `302`, and types `realm_id` as a uuid. The code is a staff `POST` with a JSON body answering `200 {external_connection_id, status, return_url}`; `realm_id` must be digits.
- [contract] README 20 (router row); `router.py:170-237`. Every `/external-connections/{...}` path parameter is `connection_id` in the contract and `external_connection_id` in the code.
- [contract] README 75; `schemas.py:128-143`, `router.py:149-156`. The contract's `ExternalConnection` (9392) returns `granted_scopes`, `settings`, `updated_at` and `authorize_url` "while pending". `ExternalConnectionOut` has none of the first three, and `authorize_url` is only on the create response, so a pending link cannot be fetched again and patched settings cannot be read back.
- [contract] README 74, 181-183 (`provider-not-configured`, `409 already-exists`); `schemas.py:117-127`, `service.py:680`, `models.py:137-139`. `createExternalConnection` (6866) lists `connection-exists` and `provider-not-available`. The code answers `422 provider-not-configured`, a generic validation `422` for an unknown provider (a three-value `Literal`: `accounting_file`, `quickbooks_online`, `zoom`) and `409 already-exists`. The contract's provider enum lacks `accounting_file`, and its create body lacks `zoom` and `settings`.
- [contract] README 184-185; `quickbooks.py:38`, `schemas.py:145-150`. `ExternalConnectionUpdate` promises "sync mode (invoice or daily summary)". The code accepts `default_income_account`, `sync_from` and `auto_sync`; there is no sync mode, and `sync_from` is not validated.
- [contract] README 165-174; `schemas.py:169-175, 195-211`, `quickbooks.py:303-351`. `runSync` (7061) answers the `Accepted` handle `{job_id, status: queued|running|succeeded|failed, resource_url}` and takes `local_kinds`. The code returns `{status, counts, status_url}` with `running|completed|failed`, has no `job_id`, adds a body `location_id` and has no `local_kinds`. `mappings-incomplete` is never raised.
- [contract] README 171 (`GET .../sync`, `.../sync/reset`); `router.py:210-221`, `schemas.py:201-211`. `getSyncStatus` (7084) and `resetSync` (7102) answer `200` with no schema and have no `security` line. `SyncStatusOut` (`idle|running|completed|failed`, `counts`, `next_on`, `last_on`, `retries_failed`, `beat_at`, `is_stale`) is not in the contract.
- [contract] README 172-174, 184-185; `quickbooks.py:257-287`, `schemas.py:158-168`. `getSyncMappings` (6983) still lists `provider-unavailable`, which the code no longer raises. `SyncMappings` has no `options_unavailable`, and `SyncMapping` (9430) has an `id` and names a `sync_mapping` table that README 160-161 says is not built.
- [contract] README 20; `router.py:244-248`, `service.py:864`. `listAccountingExports` (7024) lives at `/external-connections/{connection_id}/accounting-exports` with `business_on[gte|lte]` and `status[in]`. The code serves a flat `GET /accounting-exports` without those filters, and the contract path is not served.
- [contract] README 68-74; `schemas.py:218-231`, `models.py:157-182`. The contract's `AccountingExport` (9454) has `supersedes_export_id`, `created_at` and `updated_at`; neither schema nor model has them.
- [contract] README 90-92 (webhook stores each notification once); `router.py:229-235`, `schemas.py:191`. `receiveQuickBooksEvents` (7239) documents `200 No content` and a `429`. The code returns `{"stored": n}` and has no rate limit.
- [contract] README 69-70 (request id is a UUIDv5 of the day); `service.py:860`. The contract (`runSync` text) and `docs/adr/0012*.md` say the provider request id derives from the export id; the code derives it from `(connection, location, day)`.
- [missing] README 184-185 (lists only `sync_from`, `auto_sync`, `mappings-incomplete`, inheritance and `needs_reauth` as not built); `quickbooks.py:303-351`. ADR 0012 section 4 calls for "Sync now" to catch up earlier unexported days and for a successful export to advance `tenant.billing_locked_through_on`. Neither exists, and the README does not list them.
- [missing] README 185 (`needs_reauth` only); `quickbooks.py:100-108`, `models.py:155`, `events.py`. A refresh failure emits no `integrations.connection.failed`, notifies no Owner and never writes `ExternalConnection.failure_count`. The README lists none of these.
- [undocumented] README 92-93 (posting keys unique across kinds); `domain/journal.py:18-23`, `service.py:766-770`. Mappings match by posting key (`revenue:<category id>`, `tax_payable:<tax id>` or the bare account name), not the raw ids the contract describes. A mapping saved with a raw category id never matches.
- [undocumented] README 167-168 ("due tokens are refreshed under a row lock"); `quickbooks.py:83-107`. `credentials()` locks and reloads the row on every call, not only when a refresh is due, so mapping reads and each posting hold the lock. `refresh_if_due` (`:106`) and `get_mappings` (`:270`) catch bare `Exception`, which would also swallow a database error.
- [undocumented] README 77-78 (POST callback because a mutating GET is forbidden); `quickbooks.py:83-97, 257-287`. `GET .../sync-mappings` can refresh and reseal credentials, so this GET writes to the row and locks it.
- [undocumented] README 165-174; `quickbooks.py:303-351, 404-441`. Left out: days already failed are skipped unless `retries_failed`; today or later is `422`; a body `location_id` is ignored when the connection has its own; a non-active connection is `409`; a connection disconnected mid-job ends the job `failed`.
- [undocumented] README 169-171 (stale takeover); `quickbooks.py:314-316, 355-356, 391-437`, `jobs.py:34-36`. A sync has no job id, so after a takeover a slow first chain and the new chain share one cursor and the old chain's dead-letter `fail_sync` (`:431`) fails the new job. A job stored before `beat_at` existed is stale at once. A takeover is audited only as `integrations.sync.start`. The README also omits the `idle` status and that `GET .../sync` is gated by `integrations.sync.run` (`router.py:210-214`).
- [undocumented] README 181-183 (a pending or errored row is taken over); `service.py:659-701`, `quickbooks.py:156-172`. A takeover replaces `settings` (mappings, maps, sync cursor), credentials and starter, ends the earlier starter's link (`403 state-invalid`), and is audited as an ordinary `integrations.connection.create`.
- [wording] README 69 (`FH-<LOCATION SLUG>-<YYYYMMDD>`); `service.py:809`. The slug is upper-cased and cut to 12 characters, so two locations sharing a 12-character prefix get the same doc number for a day.
