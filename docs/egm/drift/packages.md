## backend/app/modules/packages/README.md

- [contract] The whole post-billed surface is absent from the API contract. `docs/api/*.yaml` has no `post-billed-rates`, `post-billed-closes`, `post-billed-closes/preview` or `client-packages/post-billed` path, and no `billing_mode` field (grep finds none). The router serves all of them (`backend/app/modules/packages/router.py:118`, `:263-301`), and the generated `backend/openapi.json` carries them (`/api/v1/client-packages/post-billed`, `/api/v1/post-billed-closes`, `.../preview`). The README (lines 53-68) describes the routes, but nothing says the yaml files are behind.
- [contract] `portalQuoteClientPackage` (POST `/portal/client-packages/quote`, `docs/api/openapi-people.yaml:5204-5206`) is not served: `router.py` has only the staff `/client-packages/quote` (`:96`). The README "Not built" list (lines 40-47) names only `setClientPackageRenewal` as a missing route.
- [contract] `setClientPackageRenewal` is `PUT /client-packages/{package_id}/renewal` in the contract (`openapi-people.yaml:5265-5267`, "Specified with the P1 slice"). The README does list it as folded into `updateClientPackage`, which is fine, but the contract itself still carries the route.
- [wording] The router docstring for the preview says "Every open post-billed package at the location" (`router.py:282`), and `preview_close` says the same (`postbilled.py:185`). `_plan` also lists expired packages that still have unbilled consumption (`postbilled.py:136-144`), so a preview or close can show a line for a package that is no longer open. The README "Usage" bullet (lines 63-64) and the "close always covers every package" sentence (line 67-68) do not say that expired packages are included only while they carry unbilled usage.
- [wording] README line 4 says "Backend only", but line 49 says web screens exist (`web/src/features/packages/`, including the new `PostBilled.tsx`). The two statements contradict each other.
- [wording] README lines 72-73 say "`reservation_type_id` has no foreign key yet ... add the composite FK when the lanes merge". The FK exists (`models.py:227`, `:340`) and is also on `post_billed_rate` (`models.py:506`). The README's own "Changed at integration" section (line 95) records it, so the Assumptions bullet is stale. `coupon_id` is still not created, which is accurate.
- [wording] README lines 85-86 say GET operation ids start with get/list. The served ids are renamed beyond that rule (for example `portalListClientPackages` is served as `listPortalClientPackages`), and the README does not list the renames. The post-billed routes have no contract operation ids to compare against.
- [undocumented] The README file table (lines 6-11) omits `postbilled.py`, `events.py`, `permissions.py` and `schemas.py`. `postbilled.py` is where the rates, the open-package command and the close live (276 lines).
- [undocumented] The post-billed rate routes are not described. `GET/POST /post-billed-rates` and `PATCH /post-billed-rates/{post_billed_rate_id}` (`router.py:263-277`, gate `packages.plan.manage`, `postbilled.py:48-73`) have no README mention beyond "Tiers per reservation type". Not documented: a rate is unique per active reservation type and `min_sessions` (`models.py:510-513`, error code `rate-tier-exists` at `postbilled.py:40`), and `per_session_minor` may be 0.
- [undocumented] Packages with no usage or no active rate are skipped at a close. They get no line and no charge, and an active one is not ended even when `is_auto_renew` is false (`postbilled.py:218`, `:258`). README line 68 says "A package without auto-renew ends at its close", which is true only for billed packages. An expired package picked up by `_plan` is billed but not expired again (`postbilled.py:258`, `status == "active"` guard); the README (line 64) says such packages are picked up but not this.
- [undocumented] No invoice is created when the charge total is 0 (a tier priced at 0), so `post_billed_line.invoice_id` stays null (`postbilled.py:249-253`). The README says each package gets "one `create_invoice_for_charges`".
- [undocumented] The preview reports `unsettled_count` (held credits not yet settled, taken from `sessions_reserved_count`) and a `skipped_reason` of `no-usage` or `no-rate` per package (`postbilled.py:154`, `:157`, `schemas.py:458-467`). The module docstring (`postbilled.py:8`) mentions the unsettled report, the README does not. `unsettled_count` is the package-wide reserved count, not only sessions on or before `closing_on`.
- [undocumented] The close publishes `packages.post_billed.period_closed` (`events.py:60-65`, `postbilled.py:228-229`). The README line 35 names only `packages.credit.reservation_failed`, and the other emitted events are missing too: `packages.package.sold`, `.exhausted`, `.expired`, `.renewed`, `packages.credit.consumed` and `.restored` (`events.py:15-42`).
- [undocumented] Open-package details: `share_with_related` shares the package with related clients, `is_autopay` defaults to false and `is_auto_renew` defaults to true, and the sale is gated by `packages.package.sell` at the location, not by a post-billed key (`schemas.py:443-450`, `postbilled.py:89`, `:98`). The default name is "Post-billed sessions" (`postbilled.py:101`). None of this is in the README.
- [undocumented] Permission keys. The README names only `packages.package.remove_override` and `packages.period.close`. The other eight keys (`permissions.py:15-24`) are not listed, and rate management reuses `packages.plan.manage`, a tenant-scope key, for what is location-priced data (`postbilled.py:48-73`).
- [undocumented] Internal functions that other contexts call are missing from the README interface block and integration list: `session_credit_facts` and `sales_by_seller` (`service.py:1442`, `:1427`), used by staff payroll and commissions (`backend/app/modules/staff/service.py`).
- [undocumented] `handlers.py` subscribes to `memberships.contract.activated` and `memberships.contract.cancelled` (the latter only when `cancel_packages` is set), calling `grant_contract_addons` and `remove_contract_addons` (`handlers.py:38-46`, `service.py:1263`, `:1278`). README line 10 says only "the memberships add-on events".
- [undocumented] Portal self-service routes turn off auto-renew on a package and on a series (`router.py:243`, `:248`, `service.py:1237`, `:1249`). They are in the contract but the README mentions portal routes only generically.
- [stale-docstring] The `models.py` docstring says "`coupon_id` is not created (billing coupons are build module 8)" (lines 4-5) although module 8 is built, and it says "the four `post_billed_*` tables" (line 7) as a deviation from the data model, while `docs/architecture/data-model-people.md` is the stated schema of record. The README does not state whether the data model was updated.
- [missing] README "Not built" says no refunds when a billed credit is restored later. The code agrees (billed sources stay in `post_billed_usage`, and `_usage` keeps only sources with positive net consumed), but there is no guard or warning when `restore_credit` runs on an already-billed source (`postbilled.py:121-132`).
