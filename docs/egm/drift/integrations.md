### INT-07 QuickBooks Online

- [contract] Deliberate deviation, written down in the README (lines 64-67). `completeExternalConnectionOAuth` is an anonymous `GET` (`security: []`, `x-permission: oauth-state`) with `state`, `code`, `realm_id`, `error` in the query and answers `302` (openapi-programs.yaml:6754-6779). The code serves `POST /external-connections/oauth/callback`, a staff route gated by `integrations.connection.manage` that also needs a signed-in person, with a JSON body, and answers `200 {external_connection_id, status, return_url}` (`router.py:159-167`, `schemas.py:176-188`). The yaml still describes the old shape. It also types `realm_id` as `format: uuid`, but the code takes digits only (`schemas.py:179`).
- [contract] Path parameter is `connection_id` in the contract for every `/external-connections/{connection_id}...` operation (openapi-programs.yaml:6780, 6820, 6843, 6884, 6921) and `external_connection_id` in the code (`router.py:170-227`). Same URL, different name in the generated spec and in `web/src/api/schema.d.ts`.
- [contract] `ExternalConnection` response. The contract returns `granted_scopes`, `settings`, `updated_at` and `authorize_url` "while pending" (openapi-programs.yaml:9197-9220). `ExternalConnectionOut` has none of the first three (`schemas.py:129-139`) and `authorize_url` exists only on the create response (`schemas.py:142-143`, `router.py:156`). A pending link cannot be fetched again and patched settings cannot be read back; `return_url`, `mappings`, `account_map` and `class_map` live in that same `settings` blob (`quickbooks.py:112, 280`).
- [contract] `createExternalConnection`. The contract documents `409 connection-exists` and `422 provider-not-available` (openapi-programs.yaml:6753). Code: `provider` is a four-value `Literal` of `accounting_file`, `quickbooks_online`, `zoom`, `google_analytics` (`schemas.py:118`), so any other provider (the contract's enum also lists smartwaiver, perkville and more, openapi-programs.yaml:9206) is a generic validation 422 and `accounting_file` and `google_analytics` are in the code but not the contract enum; QuickBooks with the flag off is `422 provider-not-configured` (`service.py:653-656`), not listed; a duplicate (provider, location) hits `uq_external_connection` (`models.py:138-140`) and returns the generic `409 already-exists`. The body also accepts `zoom` (the tenant's Server-to-Server app) and `settings` (`schemas.py:119-125`), which the contract schema lacks (openapi-programs.yaml:9221-9228).
- [contract] `updateExternalConnection` says settings are "sync_from date, sync mode (invoice or daily summary), auto-sync flag" and the body is `application/merge-patch+json` (openapi-programs.yaml:6811, 9229-9234). The code accepts `default_income_account`, `sync_from`, `auto_sync` (`quickbooks.py:37`); there is no sync mode, and `sync_from` is an unvalidated string (`schemas.py:146-149`; the description lists only the QuickBooks keys, not the analytics ones).
- [contract] `runSync` is a job that "creates or retries the accounting_export row of each location and day in the range" and answers an `Accepted` handle (openapi-programs.yaml:6921-6948). The code runs in the request (README line 146 says so) for one location (`quickbooks.py:300`), returns `{status: "completed", counts, status_url}` (`schemas.py:195-198`), takes `location_id` which the contract's `SyncRun` lacks, and has no `local_kinds` (`schemas.py:169-174`; contract openapi-programs.yaml:9278-9285). `mappings-incomplete` (422) is never raised: an unmapped QuickBooks key fails that day with a plain validation message (`service.py:806-807`), a revenue key with a default income account posts with a warning (:803-805).
- [contract] `listAccountingExports` is not served at its contract path (openapi-programs.yaml:6884). The flat route that is served lacks the `business_on[gte]`, `business_on[lte]` filters and the `status[in]` form (`router.py:230-233`, filter fields in `service.py:825-837`).
- [contract] `AccountingExport` response. The contract has `supersedes_export_id`, `created_at`, `updated_at` (openapi-programs.yaml:9272, 9276-9277). `AccountingExportOut` has none (`schemas.py:207-218`) and the model has no `supersedes_export_id` column (`models.py:158-186`). Main's new `runAccountingExport` returns the same schema, so it inherits this (openapi-programs.yaml:6975-6992).
- [contract] `SyncMapping` and `SyncMappings`. The contract has an `id` per mapping and a `sync_mapping` table (openapi-programs.yaml:9235-9244). The code returns no `id` (`schemas.py:152-168`) and keeps the list in `external_connection.settings["mappings"]` (`quickbooks.py:280`). The README admits the missing table (lines 141-142); the contract does not know. `external_options` is `{accounts, classes}` of `{id, name}` (`quickbooks.py:250-256`), which the contract leaves unspecified.
- [contract] `receiveQuickBooksEvents` documents `200 No content` and a `429` (openapi-programs.yaml:7072-7088). The code returns `200 {"stored": n}` (`router.py:215-220`, `schemas.py:191-192`) and neither it nor the OAuth callback has a `rate_limit` dependency (only the two public GETs do, `router.py:377`, `392`).
- [undocumented] What `local_key` must be. The contract and ADR 0012 say "tax id", "revenue category id" (openapi-programs.yaml:9242, adr/0012:158-166). The export looks mappings up by posting key: `revenue:<category id>`, `tax_payable:<tax id>`, or the bare ledger account name (`domain/journal.py:18-23`, `service.py:802`). A mapping saved with a raw category id never matches. README lines 81-82 mention that posting keys are unique across kinds but not that `local_key` must be one; `unmapped` lists the posting keys (`quickbooks.py:262`), the only hint.
- [undocumented] ADR 0012 refresh rules the README does not list as not built (its lines 156-157 name only `needs_reauth`). A refresh failure (`invalid_grant`) emits no `integrations.connection.failed` and notifies no Owner, rotation is not stored under a row lock (adr/0012:155-158; `quickbooks.py:88-92` lets the exception propagate, `events.py` has only the webhook-disabled event), and `ExternalConnection.failure_count` is never written (`models.py:155`).
- [undocumented] `getSyncMappings` and every call that needs the access token can refresh and reseal credentials (`quickbooks.py:82-92`, called at :253), so a `GET` writes. The README rationale for a POST callback ("no mutating GET", lines 66-67) does not mention it. The request transaction commits, so the rotated token is kept.
- [undocumented] `run_sync` rules the README leaves out (its line 146 gives only the 31-day cap): days already `failed` are counted as `failed` and not retried unless `retries_failed` is true (`quickbooks.py:316-317`); today and future days are refused (`last >= today`, :305); a body `location_id` is ignored when the connection has its own (:300).
