## backend/app/modules/rentals/README.md

Checked 2026-11-13 against the working tree (uncommitted `claude/rentals-pilot` edits included) and the rentals operations in `docs/api/openapi-core.yaml`. Read-only; no tests run. The pilot sections (minors rule, member prices, portal defaults) match the code; the drift is in the older text, the file table and the contract.

- [stale-not-built] `backend/app/modules/rentals/models.py:1-2` says `locker_lease` "is not built" and that resources' `locker` and `locker_term` tables do not exist. `LockerLease` is defined at `models.py:594-598`, and the README's "Lockers and plan extras" section (L85-108) describes it as built.
- [missing] README L136-137 says portal confirmation decides "secured" through `billing.checkout.is_secured`. `is_secured` exists (`billing/checkout.py:34`) but nothing in rentals calls it. `confirm_portal_rental` (`service.py:1533-1557`) passes the `secure_online_checkout` result through as `payment_status` and `_checkout` (`service.py:1492-1506`) has no secured test.
- [contract] `confirmPortalRental` request. Code takes `save_method` and `terms_version_id` (`schemas.py:454-455`). Contract `PortalRentalConfirm` (`openapi-core.yaml:6122-6134`) names the field `save_payment_method` and has no `terms_version_id`. README L152-153 uses the code name.
- [contract] `confirmPortalRental` errors. README L154-155 says a decline is 409 `payment-failed`; the contract still lists `x-problem-codes: [payment-declined, ...]` (`openapi-core.yaml:4174`), a 402 PaymentDeclined response (L4165), and 403 for a method that is not the client's. Code can also answer 422 `payment-method-not-usable` and `payment-method-required` (`service.py:1546-1548`).
- [contract] GET and PUT `/locations/{location_id}/rental-portal-settings` (`router.py:160,165`; README L141-143) appear in no `docs/api/*.yaml` (`openapi-programs.yaml:97` only mentions them). `horizon_days` on `RentalTypeOut` and `PublicRentalType` (`schemas.py:87,410`) and the `beyond-horizon` code (`service.py:1337`; README L150-151) are also not in the contract.
- [contract] Three routed operations have no `operationId` in `docs/api/*.yaml`: `updateRentalPlanPurchase` (PATCH `/rental-plan-purchases/{purchase_id}`, `router.py:262`), `portalOptOutRentalPlanAutoRenew` (POST `/portal/rental-plan-purchases/{purchase_id}/auto-renew-opt-out`, `router.py:303`) and `renewLockerLease` (POST `/locker-leases/{locker_lease_id}/renew`, `router.py:334`). README L15 says the router serves "the rental routes of `openapi-core.yaml`".
- [undocumented] The portal confirm records acceptance of the portal terms (`clients.terms.acknowledge(... sale_kind="rental")`, `service.py:1543-1544`; `terms_version_id`, `schemas.py:455`). README L152-155 describes the payment step but not this one, and the cross-context list (L80-83) omits `clients.terms`.
- [undocumented] The file table (L7-16) omits `schemas.py` (701 lines), `permissions.py`, the lockers screen `web/src/features/lockers/LockersPage.tsx`, the portal screens `web/src/features/portal/BookingsPage.tsx` and `RentalPlansPage.tsx`, and the online-booking card and plan-share dialog inside `web/src/features/rentals/RentalSetupPage.tsx:642,778`. L16 lists the setup page as "types, rates, plans, plans sold" only.
- [undocumented] Permission keys without a mention. `permissions.py:14-26` registers `rental_type.manage`, `rental_plan.manage`, `rental_plan.sell`, `rental_plan.share`, `rental_plan.remove` (flag D, "remove and refund") and `public_listing.publish`. The README names only `booking.override_rate`, `booking.override_minor`, `portal_setting.manage` and `locker_rental.manage`, and has no key table.
- [undocumented] Staff routes with no description: `PUT /rentals/{id}/public-schedule` (`router.py:137`), `PATCH /rental-plan-purchases/{id}` for `is_auto_renew` and `is_autopay` (`router.py:262`, `service.py:1809`), `POST /rental-plan-purchases/{id}/cancel` (`router.py:275`, `service.py:1779`), `DELETE /rental-plans/{id}` as archive (`service.py:1635`) and `POST /portal/rentals/{id}/abandon` (`router.py:201`).
