## backend/app/modules/documents/README.md (checked against docs/api/openapi-people.yaml)

Checked 2026-11-13 against the working tree, including uncommitted changes. This replaces the earlier report.

- [undocumented, new] `service.is_agreement(session, doc)` (`backend/app/modules/documents/service.py:575`) and `service.is_signed(session, doc_id)` (`:581`) are internal helpers for memberships (DOC-11), called from `memberships.bind_agreement` (`backend/app/modules/memberships/service.py:974`, `:978`). The README's internal interface list (lines 22-24) names neither. The README also never mentions DOC-11, binding an agreement to a contract, or the fact that memberships calls `load_document` directly (`memberships/service.py:972`), which is a permission-checked function used as if it were internal.
- [logic duplicated] `bind_agreement` computes "accepted and not deleted" inline (`memberships/service.py:973`) and then calls `is_signed` for the same test on the existing document (`:978`). The rule is therefore in two places and could drift apart. `is_signed` is also reached only through memberships.
- [no tests] Neither helper is referenced by any test under `backend/app/modules/documents/tests/`. `is_agreement` and `is_signed` are covered only indirectly, through the memberships agreement tests. In the helpers, `is_agreement` returns False for a document with no `template_id` (paper upload) and for a template with `is_waiver=true`, and no documents test pins that.
- [undocumented] The ADR 0009 section 9 internal convention ("no principal, no authorize") is stated in the README, but `is_agreement` and `is_signed` take a raw `ClientDocument` or id and do not check tenant, client or location scope. That is fine only because `bind_agreement` loads the document through `load_document` first. `is_signed` is called with `contract.client_document_id`, which is not loaded through a gate. The README does not say callers must have loaded the document.
- [missing] Lines 25-26 say selling contexts "(memberships, packages, programs, rentals)" call `requirements_for` / `ensure_pending` / `consume`. Rentals makes no call into `documents.service` (grep of `backend/app` finds callers only in memberships, packages and `programs/checkout.py`). A rental type has no document gate.
- [undocumented] `has_valid_waiver` and `settings_row` are called from memberships (`memberships/service.py:1961`, `:1963`). `settings_row` is not in the internal interface list. `has_valid_waiver` is listed. (The earlier report cited the wrong `settings_row`: memberships has its own at `memberships/service.py:137`.)
- [wording] Lines 52-53 say the paper-scan route is the only one the body-limit middleware exempts. `BodyLimitMiddleware.UPLOAD_PATHS` also covers `/clients/{id}/photo`, `/client-notes/{id}/attachments` and `/import-jobs/{id}/source` (`backend/app/core/api.py:237-241`).
- [wording] Lines 16 and 45-46 describe storage as the local-disk adapter only and give "the local-disk adapter cannot sign URLs" as the reason downloads stream. An S3 adapter with presigned GETs exists (`backend/app/adapters/s3_storage.py`). Streaming is still what documents does, but the stated reason holds only for local disk.
- [undocumented] `platform/files.py` also runs the malware scanner (`backend/app/modules/platform/files.py`). README line 17 lists sniffing, re-encoding and mismatch refusal but not scanning.
- [undocumented] `events.py` is missing from the file table and the README names no events. It emits `documents.document.sent`, `.accepted`, `.declined` and `.expired` (`backend/app/modules/documents/events.py:16,20,24,28`).
- [undocumented] `permissions.py:19` registers `documents.document.bulk_request` for the unbuilt DOC-07. The README does not say the key exists unused.
- [contract naming, partly undocumented] The README explains the renamed portal operation ids (`getPortal*`, `listPortalClientDocuments`, `getPublicPortalTerms`). The spec's `portalGetConsentState` is also renamed to `getPortalConsentState` (`backend/app/modules/documents/router.py:309`), and the README rename list omits it. The list there names `portalGet*` generically, so this is a minor gap.
- [contract, known gap] The spec defines `listClientsMissingDocument`, `createDocumentBulkSend`, `getDocumentBulkSend` and `listDocumentBulkSends` (`docs/api/openapi-people.yaml:3117`, `:3131` onward). None is implemented in `router.py`. The README's Known gaps lists DOC-07 and the missing-document audit, so this is documented drift.
- [stale code comment] The README (line 66) says `app/scheduler.py` enqueues `sweep_documents` hourly, which the scheduler confirms (`backend/app/scheduler.py:22`). The actor's own docstring still says "Nothing schedules it yet (no scheduler in the kernel)" (`backend/app/modules/documents/service.py:1272-1273`). The code comment is the stale side.
- [link suggestion] The README has no pointers to the OpenAPI file or to the memberships consumers. Adding `docs/api/openapi-people.yaml` and a short "Callers" line, including `memberships.bind_agreement`, would make future drift checks cheaper.

No operation-id drift was found beyond the items above: every implemented route matches a spec operation (allowing for the documented renames), and the Python signatures of the two new helpers are not part of the HTTP contract, so the API contract has no drift from this change.
