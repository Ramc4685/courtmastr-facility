Phase 15 additions

- [contract] `GET /portal/enrollments` is documented as returning `Enrollment` items (`docs/api/openapi-programs.yaml:7568-7599`, response at `:1375`). The code returns `PortalEnrollmentOut` (`schemas.py:538-549`), which adds `starts_at` and `ends_at` (nullable) and drops `location_id`, `pricing`, `program_fee_id`, `client_package_id`, `charge_id`, `payer_client_id`, `checkout_id`, `batch_id`, `channel`, `hold_expires_at` and `billing_disposition`. The README describes the two time fields (file table row `selfservice.py`); the contract has neither field.
- [contract] The contract lists query filters `status[in]` and `starts_at[gte]` for `listPortalEnrollments` (`openapi-programs.yaml:1361-1362`). `portal_list_enrollments` keeps only the keys `status`, `target_kind` and `client_id` (`selfservice.py:299`) and drops every other query key, so both contract filters are silently ignored (`status[in]` is not the key `status`). The router docstring says "Filters: status, target_kind, client_id" (`router.py:363`). The README does not say which filters the route has.
- [undocumented] `public_seats(..., limit=)` passes `limit` to `session_window` and drops hidden, unlisted, out-of-range and full-and-hidden sessions afterwards (`selfservice.py:203-216`). The cap counts rows before the listing rule, so a location with many hidden or full sessions can return fewer than `limit` published sessions while later published ones are cut. The caller (`integrations/feeds.py:387`, `MAX_EVENTS = 1000`) then shows a truncated public schedule with no signal. The README says "the same listing rule" and nothing about the cap.
- [undocumented] `public_seats` applies the portal rule only in part. The portal listing reports `list_only` sessions as not bookable (`_verdict`, `selfservice.py:146`); `public_seats` shows them as ordinary seats with no bookable flag. It returns scheduling's raw session views (`booking_id`, `location_id`, `fill`, `allows_free_booking`, `is_direct_link_active`), not the portal listing shape. The README row names neither.
- [undocumented] `portal_list_enrollments` returns times for every session place, including cancelled sessions, because `get_sessions` filters on no status (`scheduling/service.py:861-864`). The times are `None` for a group registration or when the session row is gone (`selfservice.py:306-310`). The README says "none for a group registration" only. It also returns plain dicts, not `Enrollment` rows (`selfservice.py:294-312`), so internal callers (`integrations/meetings.py:257`, `integrations/feeds.py:294`) read `place["session_id"]`, not attributes.
- [undocumented] No test in `programs/tests` covers `public_seats` or the `starts_at`/`ends_at` keys. They are reached only through `integrations/tests/test_meetings.py:303` and `integrations/tests/test_feeds.py`, so a regression in the listing rule would show up in the integrations suite, not here.
- [stale] README "Not built" (line 155) still lists virtual meeting links (CLS-08) as not built. Phase 15 built them in `integrations/meetings.py` (`portal_meetings`; `integrations/README.md:131-134`). Programs itself still has no `video_join` producer (README lines 161-162 hold).
