### Portal enrollment read (changed in this tree)

- [contract] `listPortalEnrollments` (`docs/api/openapi-programs.yaml:1349-1379`) was not updated with the change. It returns the shared `Enrollment` schema (7568-7599: `location_id`, `pricing`, `program_fee_id`, `client_package_id`, `charge_id`, `payer_client_id`, `checkout_id`, `batch_id`, `channel`, `hold_expires_at`, `billing_disposition`, `created_at`, `updated_at`). The code returns `PortalEnrollmentOut` (`schemas.py:537-549`), which has none of those and adds `starts_at` and `ends_at`, fields the contract does not have.
- [contract] The same operation declares `status[in]` and `starts_at[gte]` (yaml 1357-1360) and an `ActingFor` parameter. The code keeps only the exact keys `status`, `target_kind` and `client_id` (`selfservice.py:295-296`; router docstring `router.py:363`), so a `status[in]=...` or a `starts_at[gte]=...` filter is dropped silently and the full list comes back; `starts_at` is not a filterable column even though the response now carries it. `client_id` stands in for `ActingFor`. The README does not list the accepted filters.
- [undocumented] `POST /portal/enrollments` and `POST /portal/enrollments/{id}/cancel` use the same `PortalEnrollmentOut` but return the ORM `Enrollment` row (`router.py:367-376`, `selfservice.py:266-284`), which has no session times, so `starts_at` and `ends_at` are always `null` there even for a session place. Only the list fills them (`selfservice.py:302-308`). The field description says "The session's start; none for a program registration" (`schemas.py:547`), and the README (line 14) scopes the claim to `GET /portal/enrollments`, but the two other routes share the schema without saying it.
- [undocumented] No test in the programs module checks `starts_at` or `ends_at` on the portal list: `tests/test_selfservice.py:94-95` reads only the ids. The new behaviour is pinned through integrations (`integrations/tests/test_meetings.py`, `test_portal_places_carry_session_times_and_which_have_a_meeting`).
- [wording] `scheduling.service.get_sessions` is documented as "Internal (integrations' member feed)" (`backend/app/modules/scheduling/service.py:851`) but `selfservice.portal_list_enrollments` now calls it too (`selfservice.py:302`). The README says nothing about programs reading sessions in bulk for the list.
