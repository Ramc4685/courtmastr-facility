- [undocumented] The file table (README lines 8-19) now lists `handlers.py` and `events.py` but still omits `tools.py`, `forms.py`, `router.py`, `schemas.py` and `permissions.py`. `tools.py` and `forms.py` are named only in prose (README line 86 onward).

- [contract] `PortalEnrollmentCreate` in `docs/api/openapi-programs.yaml:7553-7572` has no `direct_link_token` (SCH-16, Phase 14 C2). The code accepts it (`schemas.py:535`, `maxLength 200`, nullable; in `backend/openapi.json:47187`). The YAML schema has `additionalProperties: false` (`:7555`), so by the contract the field is rejected. The `createPortalEnrollment` text (`openapi-programs.yaml:1381-1390`) does not mention direct links, and its `x-features` (`:1391`) omits SCH-16. The README documents the field (lines 64-66).
- [contract] The same YAML schema (`openapi-programs.yaml:7567-7572`) declares `pricing` (`entitlement`/`free`) and `registrant_comment`, which the code schema does not have (`schemas.py:531-535`). With `additionalProperties: false` on both sides, a client built from the contract that sends them gets 422. The auto-select of one eligible package (YAML `:7558-7559`) is also not in `portal_enroll` (`selfservice.py:211-233`). A free booking comes from `allows_free_booking` when `client_package_id` is absent, not from `pricing`.
- [wording] README lines 64-66 say a live link waives "the hidden, list-only, visible-range and self-bookable checks", and the title says the link "books a session not offered online". The code matches the list: `linked` skips `list_only` and `not-self-bookable` in `_verdict` (`selfservice.py:146-149`) and `hidden` and `beyond` in `_bookable_seat` (`selfservice.py:203-207`). But an `unlisted` session needs no link: `_bookable_seat` blocks only `hidden` (line 203, comment "unlisted stays bookable by direct link"), and `_verdict` has no `unlisted` check. Any signed-in client who knows the session id can book an unlisted session without a token. The README does not say so, and nothing enforces "bookable by link only".
- [undocumented] A token that is wrong, stale or for another session is not an error. `has_live_link` returns False (`scheduling/service.py:843-851`) and the booking falls through to the ordinary checks, so the refusal is the usual `policy-violation` with reason `list-only` or `not-self-bookable`, or `Unknown session` (422 `/session_id`) for hidden or out-of-range sessions (`selfservice.py:216-219`). Neither the README nor the contract says this. The behaviour is only in `scheduling/tests/test_sharing.py:81-93`.
- [undocumented] `portal_enroll` sets `linked` before the status check, so a link to a cancelled session still gives `Unknown session` (`selfservice.py:205-206`). `list_listings` (`selfservice.py:178-183`) never passes `linked`, so a linked session never appears in the portal listing, and it skips `unlisted` sessions as well as `hidden` ones. The README has no sentence on either, nor that the link works only through `POST /portal/enrollments`.
- [undocumented] Test coverage sits in the scheduling module only (`scheduling/tests/test_sharing.py:81-115`). `programs/tests/test_selfservice.py` has no case for `direct_link_token`, `linked=True` in `_verdict` or `_bookable_seat`, or "cutoff, membership and capacity still apply with a live link".
