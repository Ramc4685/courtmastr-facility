## backend/app/modules/assessments/README.md

- **"Not built: mobile screens" is stale (README line 52).** The mobile app has a Progress screen built on the portal bests route: `mobile/src/app/progress.tsx:21-32` uses `listProgress` → `GET /portal/assessment-bests` (`mobile/src/adapters/api.ts:177`), and `mobile/README.md:46` lists it.
- **"A result needs a location" is only an API rule (README lines 37-38).** `location_id` is required in the create schema (`backend/app/modules/assessments/schemas.py:109`). The column itself is nullable (`assessments/models.py:76`; `backend/migrations/versions/0952_assessments_core.py:77`). `delete_result` also keeps a branch for a null location that needs tenant-wide `assessment.delete` (`assessments/service.py:243-244`). The README says neither of these.
- **Permission list leaves out a registered key (README lines 24-26).** `assessments.assessment.share` (a `C` key, own reach for coaches) is registered (`assessments/permissions.py:17`) but missing from the Interfaces list. The feature it gates (`shareAssessmentResult`) is listed as not built (README line 52), and no service or route uses the key.
- **Delete needs a second gate (README line 25).** The doc gives `assessment.delete` as an `L` key on the entry's location. `delete_result` first loads the entry through `_result(..., READ)`, which also requires reaching the client with `assessments.assessment.read` (`assessments/service.py:152-157, 242`). Only then does it check the `L` key (`service.py:246`).
- **Data-subject export is not documented (README line 29).** The doc says only "Merge moves every entry...; erasure deletes the client's entries (`subject.py`)". `subject.py` also registers an export handler (`assessments/subject.py:19-28, 39`) that returns every entry's `recorded_at`, staff `note` and values.
- **History filters are documented on both reads, but the list has fewer (README lines 15-16).** "Filters: field ids, category, time window" follows both `listAssessmentResults` and `getAssessmentSeries`. Only the series takes field ids and category (`assessments/service.py:255-266`). `list_results` allows only `client_id` and `recorded_at` filters (`service.py:192`).
- **Web screens are not mentioned.** `web/src/features/assessments/AssessmentSetupPage.tsx`, `ClientAssessmentsTab.tsx` and `PortalProgress.tsx` implement setup, the client history tab and the portal view. The README has no screens section or pointer to them.
