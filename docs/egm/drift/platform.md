## backend/app/modules/platform/README.md

Re-checked against the code on branch `claude/coach-share` (2026-11-13). README line numbers are the current ones. Only divergences are listed. The platform key count (31, README:15) matches `permissions.py`. The six events (README:12) match `events.py`. The branch's staff and coach-share changes do not touch platform.

- [contract] README:23 says "Other contexts use `service`, `auth` and `staff` only, never the models". Non-test code in other contexts still reads `platform.models` directly: `clients/files.py:29` (`StoredFile`), `clients/households.py:383,449` (`Identity`, `TokenPurpose`), `clients/activity.py:269-270` (`StaffUser`, `Identity`), `reporting/service.py:400` (`StoredFile`), `reporting/schedules.py:176` (`StaffUser`), `imports/service.py:100` (`StoredFile`), `documents/service.py:647` (`StaffUser`). Contexts also call `files`, `entitlements`, `retention`, `onboarding`, `privacy`, `branding` and others, which the README itself presents as cross-context APIs (README:17-18, 354-356, 383-398). Reword the rule or move the reads behind `service`.
- [wording] README:5 says the module "Calls no other context", but README:23-24 names `privacy` as an exception, and `privacy.py:89-92` lazily imports `app.modules.clients.service`. Line 5 contradicts line 23.
- [wording] README:23-24 says `privacy` "calls `clients.service` for erasure". The import is used only for `clients.get` (`privacy.py:89-92`). Erasure and export run through the registered `HANDLERS` (`privacy.py:81`, used by the request flow).
- [undocumented] The data-subject handler registry is not described in README:392-398: `SubjectHandler` and `register_subject_handler(context, *, tables, export, erase, precheck)` (`privacy.py:73-85`), the `HANDLERS` fan-out, and the rule that each context holding client data registers one (e.g. `engagement/subject.py`, `programs/subject.py`, `billing/subject.py`, `access/subject.py`, `pos/subject.py`).
- [undocumented] Turning GDPR mode off is not described (README:392-398 covers only mode on). `put_privacy_settings` runs `GDPR_OFF_HANDLERS` in the same transaction and audits `implied_consents_withdrawn` (`privacy.py:57,64-68`).
- [undocumented] README:9 lists cross-context helpers in `service.py` "and others" but names none of `tenant_hosts` (`service.py:583`, used by `engagement/service.py:1760`), `location_today` (`service.py:321`), `earliest_today` (`service.py:329`, mentioned only in passing at README:345) or `location_todays` (`service.py:337`, used by `reporting/service.py:138`).
